# Design

## Context

动机和阶段范围见 [proposal.md](proposal.md)。L00 建立了规划与文档；用户已 review，按单课推进实现，模型资产仍不在 L01 范围内。

MiniMind 参考版本为 `233d00fa068ec2b8c0d4f07b703934d6391a5a73`。其原生训练链路适合阅读，但本项目采用已确认的库优先路线，不复制整仓。用户已改为本机 Windows/5070 优先开发测试和训练，遇性能瓶颈再迁移另一台 Windows/5090；后者仍无运行证据。

## Goals / Non-Goals

**Goals:**
- 将每课做成小型可运行入口，数据与计算过程能被逐项观察，不提前搭完整训练框架。
- 数据/tokenizer/model 身份显式关联，运行路径不依赖开发机位置，安装说明可支撑另一台电脑复现。
- CPU tiny 测试承担大部分正确性反馈，目标 GPU 探针承担真实设备兼容性验收；两类证据不互相冒充。

**Non-Goals:**
- 不同时维护多套模型实现或多平台安装矩阵。
- 不在第一阶段引入分布式、性能 kernel、Agent 框架、Notebook 平台或完整训练调度。
- 不把后续协议字段、工具结果和在线奖励提前塞入当前纯文本数据实现；未来扩展仍需遵守已记录的消息/训练边界。

## Decisions

### 1. 一个首阶段 change，八个学习提交

任务状态只在本 change 的 `tasks.md` 维护，总路线放 `.claude/plans/LLM训练全流程教程.md`。L00 只提交规划，L01–L08 每课在用户授权后交付实现、测试和教程，并暂停。自主模块维护在 `docs/extensions/index.md`，不作为当前待完成任务。

备选是一次建立所有后续 change 或每个函数一个任务；这会把路线预想当成执行承诺，故不采用。

### 2. Windows/5070 优先，5090 按需迁移

本机已确认 Windows 11 专业版 x64、build 26100，RTX 5070 约 12GB、驱动 591.59。用户另有 Windows/5090；本阶段不要求先到另一台电脑执行。先用原生 Windows 的隔离环境完成 CPU 与本机 CUDA 验证，不安装 WSL 或修改驱动。

`docs/setup/README.md` 记录本机安装/重建步骤、版本、探针与排障；5090 的迁移命令复用同一 Git revision 与锁文件，但必须在迁移时重新运行探针。若性能瓶颈需要改变模型规模、平台或库，先让用户决定。

通过支持 RTX 50 系列的预编译 CUDA wheel 起步，不额外安装完整 CUDA Toolkit。L01 的真实 GPU 验收是 5070；保留 5090 未验证的事实，而不是把未验证当成课程阻塞。

### 3. 依赖按课程添加，版本通过实测锁定

使用 Python 3.11 项目环境和 uv 锁文件。L01 选择官方索引的 PyTorch 2.10.0+cu128、NumPy 2.4.6、pytest 8.4.2，包构建使用 hatchling 1.27.0；只支持当前选定的 Windows x64 安装路径。Tokenizers、Transformers、Datasets 在对应课程加入，不把全局 CPU Torch 带入项目。

不复制 MiniMind requirements，也不混装最新版本。torch 绑定专属官方 CUDA 索引，其他包从 PyPI 解析；安装文档记录来源和锁文件复现方式。本组合已通过本机真实 CPU/CUDA 探针、NumPy/PyTorch 互转和测试；后续依赖变化必须再次验证。

### 4. 主线 tokenizer 固定，toy BPE 独立

L03 引入固定版本的 MiniMind tokenizer 资产，记录获取方式、哈希和许可证，不通过 `../minimind` 读取。下载范围限于实际需要的资产，离线测试使用微型 fixture；不下载训练数据集或模型权重。

L04 使用显式训练用途的自写微型语料练习 BPE，产物进入独立实验输出，不能替换主线 tokenizer。词表改变应开启新模型实验，而非继续使用原模型 embedding。

### 5. 文档级数据处理后再构造 batch

L05 初始输入使用带来源标识的文本记录。先检查字段/空值，做精确文本去重，按文档标识与固定 seed 切分，再分块。处理清单记录输入身份、保留/拒绝数量及配置；近重复检测作为自主扩展，不声称精确去重解决所有污染。

L06 明确唯一的 next-token 对齐位置：数据提供与输入同位置的 labels，padding 对应 `-100`；模型计算 loss 时对齐下一 token。测试用手工序列核对预测目标，确保不重复 shift、不把有效 EOS 当成 padding。

toy BPE 的训练 fixture 在 L04 独立声明用途，不依赖尚未实现的 L05 管道；L05 后处理真实切分时继续遵守训练/验证隔离。

### 6. 模型库承载主线，实验解释数学与数据流

L02 使用小函数对照解析梯度和 autograd；L07 使用小矩阵和 PyTorch SDPA 检查 causal mask，RMSNorm/RoPE/GQA 的手写替代保留给自主模块。

L08 使用 Transformers 原生 Qwen3 配置随机创建模型，不调用加载预训练权重的路径。显式设置层数、hidden size、head dimension、词表与特殊 token ID，报告参数量并核对 `[B,T,V]` logits 和有限 loss。

tiny 起点建议 2 层、hidden 128、短序列；实现时检查各维度整除关系。它用于机制验证，不评价聊天质量，也不因 5090 资源更大而自动提高训练规模。

### 7. 逐课目录与验证对应

以下是实施目标，不是已经存在或执行过的文件；课程实现时才确定可直接运行的命令。

| 课程 | 主要交付位置 | 验证关注点 |
|---|---|---|
| L01 | 依赖/锁文件、设备探针、`docs/setup/README.md`、L01 教程 | 本机 CPU/5070 的真实计算，隔离环境重建；5090 留待迁移 |
| L02 | 张量/梯度实验与测试、L02 教程 | 解析梯度、参数更新与目标变化 |
| L03 | tokenizer 获取/检查入口、资产来源清单、L03 教程 | 编解码、ID/特殊 token、重载身份 |
| L04 | 独立 BPE 实验与训练 fixture、L04 教程 | 训练隔离、空输入、保存/重载 |
| L05 | 语料准备与测试、L05 教程 | 去重、拒绝原因、确定性文档切分 |
| L06 | batch 构造与手工序列测试、L06 教程 | next-token 目标、PAD/EOS、有效位置 |
| L07 | 注意力实验与因果性测试、L07 教程 | Q/K/V 形状、未来 token 扰动不影响过去 |
| L08 | 模型配置/初始化与测试、L08 教程 | 无预训练权重、参数量、身份、输出与 loss |

`src/llm_tutorial/` 放可复用主线，独立数学实验可放 `experiments/`；不在 L01 一次性搭出后面所有空模块。每课的测试和教程必须随本课交付，不留到阶段末尾。

## Risks / Trade-offs

- [5090 环境尚未验证] → 先在本机 5070 完成课程，迁移时重新验证；不承诺相同驱动或性能。
- [小模型能力很弱] → 本阶段只验计算与数据契约，不承诺能对话或使用工具。
- [依赖版本/新 GPU 架构不匹配] → 最小 CUDA 探针先验证，必要变化先 review，不通过退出码或设备列表猜测。
- [tokenizer 与模型身份错配] → 记录资产/配置标识，输入范围和特殊 token 映射不一致时明确报错。
- [跨机器数值不完全一致] → 确定性对照优先 CPU；GPU 明确 dtype 与容差，不承诺跨硬件位级相同。
- [原始数据或权重入库] → 只跟踪小型许可 fixture 与可复现清单，真实产物进入忽略目录。

## Migration Plan

这是新仓库，无旧系统迁移。review 已通过，从 L01 单课推进，5070 优先承担开发、测试与可承受的训练。遇到实测瓶颈后，再由用户在 Windows/5090 checkout 相同提交、按文档安装并重新验证；不复制虚拟环境目录。

回到旧学习状态依靠对应 Git 提交和记录的依赖/资产身份；不改写已交付课程历史、不自动删除用户实验产物。阶段任务和验收都完成后再按项目要求归档，不能现在把首阶段标为已实现。
